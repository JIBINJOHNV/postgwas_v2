## 0. Scope and method

**Read in full (line by line):** all 33 modules of `modules/harmonisation/` (~29,300 LOC), the `concordance/`, `shared/` and `adapters/gwas2vcf/` sub-packages, `config/models/modules/harmonisation.py`, the 243 KB `config/defaults/modules/harmonisation.yaml` (149 policies across 22 groups, sampled programmatically), the supporting `core/` modules it depends on (`pipeline_logging`, `processes`, `paths`, `io/*`, `statistics`, `dataframes`, `vcf`, `values`), `pipeline/{registry,planner,executor,cli,runners}.py`, and the 25 `tests/test_harmonisation_*.py` files plus `test_architecture.py`.

**Method.** Data flow was traced first — the dataset-level stage and the sixteen per-chromosome steps — before any judgement was formed about an individual step, because several of the findings below are *ordering* problems that are invisible when a module is read in isolation. Every candidate finding was then re-grepped across `src/` to confirm it is not already compensated elsewhere; a number of candidates were discarded at that stage (noted in §7). The highest-severity findings were independently re-verified against the exact cited lines, and where behaviour depended on a numeric or library detail it was executed (`sys.exit()` status, `np.float32` cast behaviour, YAML default extraction).

**Confidence column.**
`CONFIRMED` = the code path was read end-to-end and does what the finding says.
`PLAUSIBLE` = the code is as described, but the impact depends on a caller, a config value, or a third-party library behaviour that could not be fully resolved from the staged copy.
Findings marked **✔** were additionally re-verified line-by-line during a second pass.

**Staged-copy limitations (stated so nothing is over-claimed):** `postgwas/modules/qc_summary/`, `postgwas/modules/formatting/` and the top-level `postgwas/cli/` package were not available; claims touching them are marked `PLAUSIBLE`. `polars`/`pydantic` were not installed, so nothing that requires them was executed.

## 1. What the module does — data flow

Understanding this order is a prerequisite for §3; several findings are ordering defects.

### Dataset stage (`service.run_harmonisation_pipeline`)

```
validate_config (no file read)
  → validate_header (one line read)
  → read_summary_statistics (full eager parse; immutable source_snapshot cloned)
  → validate_content
  → resolve_duplicate_variants
  → study_properties.resolve_study_properties
        _decide_effect_type → _decide_pvalue_type → _decide_or_se_scale → _decide_eaf_is_maf
  → genome_build.infer_genome_build
  → preflight_harmonisation_resources           (before any worker starts)
  → chromosome_partition.write_chromosome_partitions
  → harmonise_chromosomes  ── ProcessPoolExecutor(spawn), retry rounds
  → concat_vcfs_by_build → post-merge QC (01..05) → cleanup → run manifest
```

### Per-chromosome stage (`service.process_one_chromosome`, 16 steps)

| # | Module | Effect on the statistics |
|---|---|---|
| 01 | `pl.read_csv` | — |
| 02 | `coordinates` | chr/pos normalisation, chromosome rename map, allele pattern checks |
| 03 | `effect_type` | **OR → ln(OR)**; `SE := SE/OR` iff `se_scale=as_given` |
| 04 | `allele_frequency` → `strand` | on swap: `β := −β`, `Z := −Z`, `EAF := 1−EAF`; **SE untouched** |
| 05 | `sample_size` | `Neff = 4/(1/N_case + 1/N_ctrl)` |
| 06 | `effect_from_z` | fills whichever of BETA/SE is absent (Zhu reconstruction) |
| 07 | `p_values` | scale detection (raw / −log10 / −ln), clip, flag |
| 08 | `standard_error` | `SE = \|β / Φ⁻¹(1−p/2)\|` — only when no SE column exists at all |
| 09 | `z_score` | `Z = β/SE` (or retains a supplied Z) |
| 10 | `effect_validation` | the validation gate |
| 11–13 | `imputation_quality`, `variant_identifiers`, `effect_validation.final_completeness_check` | |
| 14–16 | `gwas2vcf_export` → `gwas2vcf_runner` → `vcf_processing` | TSV export, adapter, bcftools norm/annotate/csq/liftover |

**The ordering itself is correct** on the three axes that usually break: OR→log(OR) precedes allele swapping; `Neff` exists before it is consumed; the exact `SE = β/Z` is attempted before the lossy SE-from-p; and `Z` is recomputed last so it can never be stale. The defects below sit *inside* steps, with the exceptions noted in F-19 and F-26.

### Test-quality observations

- **Tautology.** `test_harmonisation_effect_from_z.py:49` asserts `BETA == SE * 2.0`. Since `BETA = z/√den` and `SE = 1/√den`, this holds **identically** for any denominator — it is true if `2p(1−p)` becomes `p(1−p)`, if `(N_eff + z²)` becomes `N_eff`, or if the square root is dropped. The scientific content of the only formula that produces effect sizes for Z-only studies is unprotected. Correct assertion for `z=2, p=0.25, N_eff=1000`: `SE ≈ 0.0515388`, `BETA ≈ 0.1030776`.
- **Structural, not behavioural.** Four tests (`logging.py:39`, `resource_preflight.py:335`, `screen.py:32,61`) use `inspect.getsource()` and compare `str.index()` positions of call-site substrings. `resource_preflight.py:338` asserts preflight is called before partitioning — which passes if either call is in a dead branch or a comment, and breaks on any harmless rename. The critical scientific ordering (OR normalisation before allele swapping) is protected by a **source-text assertion**, not by behaviour.
- **Over-mocking at the top.** `test_harmonisation_manifest.py:127-170` patches **14 collaborators** around `run_harmonisation_pipeline` — the only test touching the top-level entry point exercises zero science. `test_harmonisation_vcf_merge.py` writes `b"v"*200` as "VCF" files.
- **No golden fixtures, no end-to-end test.** No expected-output VCF, no expected reject file, no checked-in harmonised TSV. The single test that produces a real VCF (`gwas2vcf.py:195`) asserts only `record.id` and the sample name.
- **Machine-specific fixtures.** `tests/data/harmonisation/manifest_v2.csv` hardcodes `/Users/JJOHN41/Documents/...`, and `test_harmonisation_sample_sheet.py:44-48` asserts the path **literally equals** that absolute string. There is **no skip marker anywhere in the suite** and no `conftest.py`, so at least four tests can only pass on one developer's machine. The 29 MB ADHD file is used only for existence/size checks — never for a scientific regression, despite the fixture README claiming otherwise.
- **No property-based testing.** The module is full of algebraic invariants (`Z = β/SE`, `Φ(Z) ↔ p`, swap∘swap = identity, revcomp∘revcomp = identity, `AF + swap(AF) = 1`) and `hypothesis` appears nowhere.

- **A hardcoded default sample size** — does not exist. Every N comes from a column or an explicit configured value; missing-N imputation is opt-in with a dataset-wide fill computed before the split. This is the single most common serious error in this class of tool and it is **absent here**.
- **A magnitude filter on |β|, |SE| or |Z|** — does not exist. The only threshold is `validation.se_division_floor = 1e-12`, which guards a division. Large true effects at rare variants are not dropped for being large.
- **Shell injection in the live path** — every live command is an argv list; the two piped stages use `bash -c` with `set -euo pipefail` and `shlex.join`. Paths with spaces are safe. (The one `os.system` file is dead code, listed above.)
- **Sign loss in `SE = |β/z|`** — the sign is deliberately discarded (SE must be positive) and restored exactly at step 09 as `Z = β/SE`. Correct.
- **`sys.exit` in library code** — verified absent across `service.py`; the only `SystemExit` is in `cli.py`. The stated rationale is correct and the invariant holds. (The adapter is a separate vendored program — that is Critical #1.)
- **Non-determinism from parallel completion order** — chromosome iteration is sorted, merge input order follows that list, duplicate ranking always terminates in `input_order`, and every `.unique()` uses `maintain_order=True`. Completion order does **not** affect output bytes. The reproducibility risks are the completion-dependent EAF vote and glob-based output selection, not parallelism.
- **Pickling across the spawn boundary** — everything crossing is picklable (`Policies` defines `__reduce__`; `PipelineLogger` defines `__getstate__/__setstate__` and is never actually sent). No shared mutable state is assumed.
- **YAML bloat** — the 243 KB defaults file is **documentation, not bloat**: 59.7% is `help:` prose, median 980 chars per policy, **zero duplicated help strings**, every policy carries `origin`. A programmatic diff of the `module:` block against `HarmonisationConfig` annotations found **no** field in one and not the other.

## 9. Overall assessment

This is a **substantially above-average harmonisation implementation**, and considerably more careful than most tools in this space. Three things in particular are genuinely well engineered and are the reason the defects above are findable at all:

1. **The reject/provenance model.** `RejectCollector` with `fill_null(True)` masking, exact keep/reject complements from a single `partition_by`, an unregistered-reason guard that raises, one-rejection-per-source-row enforcement, exact snapshot matching, and a `reconcile()` conservation law enforced as a hard error. Very few pipelines in this domain can tell you where a variant went.
2. **The refusal to guess.** `strand.py` hard-fails without an EAF/MAF decision, without an effect-type decision, and refuses to orient odds ratios whose SE scale is unresolved. `effect_type.py` raises rather than assuming a log-odds scale. `p_values.py` refuses to guess between the two log scales. `sample_size.py` refuses a lone case count with the correct 2×–4× justification. These are exactly the right failure modes, and they are rarer than they should be.
3. **The policy registry.** 149 policies with plain-English help, `origin`, typed validators rebuilt from spec, all problems reported at once, immutable and picklable for worker fan-out, and `changed_from_default()` recorded into both the log and the manifest.

The **flip-vs-swap distinction is correct** — the single most important thing in the module. Four orientations are enumerated explicitly, output alleles always come from the reference, and β/Z/EAF are transformed *only* on swap, with SE correctly left alone. A `reverse_complement` (non-swapped) match rewrites the allele letters without touching any statistic. That is right and should be preserved verbatim.

**Where it falls short** clusters into four patterns:

- **Safety nets that provably cannot fire.** `max_reject_fraction: 1.0` (arithmetically unreachable), the `underflow` mask in `p_values.py` (logically unreachable), the liftover failure gate measuring the wrong denominator, `z_pval_concordance` being algebraically vacuous for the studies it exists to police, and the palindromic ambiguity band using `&` where `|` is needed. Each of these looks like protection in code review and provides none at runtime.
- **Shipped defaults that contradict the file's own recommendations.** `max_reject_fraction` (rec. 0.95), `liftover_swap` (rec. `update_tags`), `chromosome.rename_map` (rec. includes 25→XY, 26→MT), `mlogp_max` (rec. `null`, which disables the flag), `af_discordance_action: warn`, `declaration_mismatch_action: warn`, `population_frequency_qc.on_error: warn`. The recommendations are right; the defaults are not.
- **A provenance boundary at step 13.** Everything before it is rigorously accounted; everything after it (TSV export → gwas2vcf → bcftools) asserts `removed=0` while nine drop points in the adapter discard variants into a debug log that is never enabled. That boundary is where a wrong genome build or a `chr1`-vs-`1` mismatch turns into a small VCF and a green run.
- **No resource governance and no resume.** `execution.memory_gb` is accepted and never read; polars' thread pool is unbounded; peak memory is ~4× the parsed frame before any worker starts; and `core/completion.py` — a complete resume framework — has zero call sites while the CLI re-runs the entire dataset on any failure.

The **test suite protects the orientation matrix very well and almost nothing else that matters**: the Zhu reconstruction is guarded by a tautology, the log-scale p-value conversion is never exercised, `reconcile()` has no test, and the final VCF write is unverified.

**Verdict:** the science is sound in design and mostly sound in implementation. The risk is concentrated in *detection* — several genuinely dangerous conditions (transposed EA/OA, wrong build, wrong INFO scale, adapter failure) are individually plausible and are each guarded by a check that warns, cannot fire, or measures the wrong quantity. Fixing the twelve must-fix items below is mostly a matter of changing defaults and adding gates, not of rewriting science.

## 10. Must-fix

Ordered by the damage a silent failure would cause.

1. **`adapters/gwas2vcf/main.py` — replace every bare `sys.exit()` with `sys.exit(1)`, and add `expected_outputs=` to the `run_checked_command` call in `gwas2vcf_runner.py:78`.** Today a column-mapping error produces an empty VCF and exit 0.
2. **Make `ALLELE1`/`ALLELE2`/`A1`/`A2`/`AL1`/`AL2` an ambiguous alias tier requiring user confirmation.** SAIGE-format inputs are currently mapped with effect and other alleles reversed, silently, and nothing downstream can detect it.
3. **Apply the deferred `1−EAF` swap flip on the `on_maf_check_inconclusive: accept` path** (`allele_frequency.py:1428`), and set `frequency_is_aligned=True` once the column is adopted so the AF-concordance check is not disabled in the same branch.
4. **Return `"inconclusive"` from `confirm_eaf_with_reference` when `reference_minor_fraction > maf_cutoff`**, and require a minimum error margin before deciding. Today the no-information case is resolved by assuming EAF.
5. **Resolved: palindromic strand now requires strong full-study non-palindromic consensus.** Reference AF is post-orientation QC only, with palindromic discordance rejected by default.
6. **Ship `validation.max_reject_fraction: 0.95`** (the file's own recommendation) and evaluate the fraction against `rows_read` across all steps. The guard is currently arithmetically unreachable.
7. **Stop rejecting genuine p < 1e-300.** Distinguish "clipped because out of range" from "floored at the numeric bottom"; only the former should set `__se_from_clipped_pval`. This currently deletes the lead SNPs of large GWAS whenever the study supplies BETA + P and no SE.

## 13. Already correctly implemented — do not change

These are load-bearing and several are subtle enough that a well-meaning refactor would break them.

**Allele orientation**
- **Flip and swap are genuinely distinct.** `strand.py:293-312` enumerates four orientations with a separate `__strand_swapped` boolean; output alleles always come from the reference (`:452-453`) while β/Z/EAF are transformed **only** on swap (`:455-469`). A `reverse_complement` (non-swapped) match rewrites allele letters without touching any statistic. **This is the single most important thing in the module.**
- **The flipped set is complete and correct**: β negated, `imp_z` negated, EAF → `1−EAF`, SE left alone. Steps 06 and 09 both run *after* orientation, so derived quantities inherit the correct sign.
- **`shared/allele_join.py`** — the swapped reference frame re-keys `ea`↔`oa` *and* applies `swapped_value="one_minus"` in the same `select`, so a swapped match can never deliver a same-orientation frequency; callers pass `one_minus` for AF and `same` for INFO (correct — INFO is allele-independent). Direct orientation has deterministic precedence via concat order + `keep="first"`, one join, row-count preservation asserted. The reference deduplicator never picks among differing values and counts nulls as distinct via `n_unique()`.
- **`shared/variant_columns.py`** — forcing chromosome/ID/allele columns to `String` from the first read prevents polars inferring an allele column of `T`/`F` as boolean or `01` as integer. Cheap and load-bearing.
- **`genome_build.py:280-287`** — excluding palindromic pairs *and* requiring all four alleles length 1 before a variant contributes strand evidence. This is the correct rule.
- **`allele_frequency.py:594-628, 1442-1451`** — excluding palindromic variants from the MAF/EAF reference comparison, reusing the aligned column from strand orientation rather than re-reading, and deferring the `1−EAF` swap for MAF-like columns until the reference confirms alignment. Subtle and correct.

**Statistics**
- **Step ordering.** OR→ln(OR) strictly precedes allele swapping; `N_eff` exists before it is consumed; exact `SE = β/Z` is preferred over the lossy SE-from-p; `Z` is recomputed last.
- **`detect_or_standard_error_scale`** — comparing `ln(OR)/SE` against `ln(OR)/(SE/OR)` versus a supplied Z is the strongest available test; excluding variants indistinguishable under tolerance rather than counting them for both sides is correct; falling back to `−log10 p` via `log_ndtr` is the numerically right choice; refusing a score/LR/one-sided p is scientifically correct.
- **Zhu reconstruction** (`effect_from_z.py:558-572`) matches PMID 27019110 exactly, uses **EAF** (not MAF), uses the correct `N_eff`, and rejects `EAF ≤ 0 | EAF ≥ 1` with `<=`/`>=` rather than `<`/`>` — the comment explaining that the denominator is *exactly* zero at the boundary and yields `inf`, not null, is right.
- **`N_eff = 4/(1/N_case + 1/N_ctrl)`**, refusing a lone case count with the 2×–4× justification, and `use_ncontrol_as_total` for quantitative traits. **No hardcoded default sample size exists anywhere** — the single most common serious error in this class of tool, and it is absent.
- **`shared/statistics.two_sided_negative_log10_p_from_z`** uses `scipy.special.log_ndtr`, accurate into the far tail where a hand-rolled `−log10(2(1−Φ(|z|)))` would catastrophically cancel. One implementation, shared by both consumers.
- **`negln` handling** — dividing by `ln(10)` into a scratch column and reusing the single `−log10` code path, with an explicit refusal to guess between the two log scales.
- **Finiteness before positivity** (`effect_validation.py:349-373`, `z_score.py:201-207`), with the `inf > 0` rationale spelled out in comments worth keeping.
- **`pvalue.zero_missing_se = fail`** — refusing to fabricate an SE from a censored p = 0, with an actionable message naming the three escapes.
- **`adapters/gwas2vcf/pvalue_handler.py:34-41`** — `LP` is genuinely `−log10(p)`, computed with `decimal.Decimal(Emin=-10000000)`, preserving p far below float64's normal range. **Do not replace this with numpy.**
- **`gwas.py:86-97` `reverse_sign`** flips REF/ALT, negates `b`, negates `imp_z` **and** sets `alt_freq = 1 − alt_freq` together, in one place, correctly leaving the p-value alone.

**Accounting, safety and execution**
- **`rejects.py:367-434`** — the `fill_null(True)` rule and the single `partition_by` producing exact complements; the unregistered-reason guard; one-rejection-per-source-row; exact snapshot matching. The strongest part of the module.
- **`rejects.py:745-774` / `cleanup.py:67-106,173-370`** — write-to-temp → validate → `os.replace` → only then unlink sources; the `move_complete` gate refusing to delete anything if a single archive move failed; `_safe_name` rejecting path separators in config-derived filenames.
- **`vcf_processing.py`** — every command is an argv list; the piped stages use `bash -c` with `set -euo pipefail` and `shlex.join`. `bcftools norm -m-any -d exact --fasta-ref` before and after liftover supplies the indel left-alignment the Python layer does not do. `--pair-logic exact` on both dbSNP and panel annotation means a non-matching variant receives **no** annotation rather than a mis-oriented one. The zero-survivor invariant (`:515-526`) is a correctly non-configurable floor. Merge retries are idempotent (`unlink` → `expected_outputs` → size check → `index -n` record count), and per-chromosome inputs are deleted only when their merge produced a validated output.
- **`gwas2vcf_export.py:100-132`** — requiring audit columns present, fully non-null and disjoint from mapped columns is load-bearing: because `strand_action` is written last and can never be empty, the adapter's `line.strip().split()` can never lose a trailing field and shift column indices. **Do not relax this and do not reorder `export_df`.**
- **Resource preflight** — the strongest engineering in the module. Existence, non-emptiness, readability, `.tbi/.csi` presence *and* `bcftools index --stats` parse, exact contig presence with non-zero records, `##INFO` tag presence **and** `Number=A|1, Type=Float`, `.fai` integrity, reference-table headers, GFF shape, 13-field chain records, and chain-source→target-contig compatibility — all before the fan-out, aggregated into one report, with cheap worker-side re-checks.
- **No `sys.exit` in library code**, with the correct `SystemExit`-derives-from-`BaseException` rationale; worker screen-text buffering with single-threaded parent printing; `screen_order` blocks flushed from a `finally`; append-mode flush-per-record logging so a SIGKILLed worker still leaves a complete log; `logger.qc()` requiring `before`/`after` as **positional** arguments so a QC action without counts is a `TypeError`.
- **`_derive_parallelism` shrinks threads before workers** with the stated reason ("a worker that cannot start does no work at all") and emits a `DECIDE` record with the evidence.
- **`run_checked_command` / `run_supervised_process`** — argv-only, `expected_outputs` verified after a zero status, stdout streamed to a file rather than held in memory, POSIX process-group isolation with SIGTERM→grace→SIGKILL escalation.
- **`qc_reporting.py:19-60`** — `_available`/`_count`/`_percent` return the literal string `"unavailable"` rather than fabricating a zero, and `_percent` refuses a non-positive denominator. The right instinct throughout the reporting layer.

**Input handling and configuration**
- **Three-stage validation ordering** — config-only → one header line → parsed frame, each collecting *all* problems, each rendering an actionable report with the actual column list. `ConfigError` deliberately derives from `Exception` so one bad dataset does not kill the batch.
- **Case-sensitive column matching with a "did you mean" that distinguishes case-only differences from fuzzy near-misses.** Failing loudly on a case difference is the right call for allele columns.
- **`resolve_duplicate_variants`** — policy-driven grouping key, exact agreement required on non-null consistency fields, conflicting groups removed *in full*, deterministic ranking always terminating in `input_order` (enforced by a cross-check), collision-free temporary names, full reject provenance for both classes.
- **`study_properties`** — every denominator over the non-null subset, one combined full-frame aggregation for all evidence, detectors delegated to the owning modules rather than reimplemented, and `StudyPropertyError` rather than a silent guess when a column has zero usable values.
- **`policies.py`** — data-in-YAML with typed validators rebuilt from spec, all problems reported at once, immutable picklable `Policies`, `changed_from_default` recorded to both log and manifest, YAML-reserved-word quoting, `group_order` completeness enforced at load.
- **`sample_sheet_generator` guards** — refusing ALT-frequency as EAF unless the effect allele is ALT-labelled, refusing to assume a total-N column is a control count when cases exist, refusing `WEIGHT` as a sample size, and atomic `mkstemp` + full round-trip reload before `os.replace`. **`SampleSheetColumnAliases.aliases_do_not_cross_scientific_fields`** is what makes `_one_match` safe within a category.
- **Concordance** compares the **original input summary statistics** against the harmonised merged VCF — an independent re-derivation, not a self-check. Allele-order-insensitive canonical keys, a ±1 `orientation_factor` applied to β and Z (correct: on the log-odds scale a swap negates β and leaves SE unchanged), MAF-vs-EAF handled separately, `norm.isf(p/se_tail)` for Z-from-p, SNP/indel/other strata evaluated independently, and an explicitly-labelled *upper bound* for indel representation pairs that never claims a specific indel was retained. Its **streaming architecture** (`scan_csv → sink_parquet`, chromosome-partitioned sequential comparison, lazily combined report fragments) is what the harmonisation dataset stage should look like.
