# Fine-mapping scientific corrections

The public return keys are preserved. Both engines default to a 95%
credible-set target and record any explicit schema-validated coverage override.

| Area | Implemented correction | Scientific reason |
|---|---|---|
| SuSiE credible sets | Every `susie_rss` call, including recovery calls, explicitly uses the one resolved YAML coverage target; exported component coverage is checked against it. | Recovery must not silently change the inferential target. |
| SuSiE PIP export | FLAMES `prob1` is the SuSiE global PIP for each member of the component-defined credible set at the resolved coverage target. | Component `alpha` defines membership; global PIP is the SNP-level inclusion probability expected by FLAMES. |
| SuSiE mapping | Model indices are restored before mapping PIP, alpha, effect moments, and log Bayes factors to variants. | Sorting or merging without index restoration can attach posterior values to the wrong SNP. |
| Alleles and LD | Summary alleles are aligned to the allele counted by the LD matrix; z-score/beta signs are flipped on swaps. Strand-ambiguous A/T and C/G SNPs are excluded without frequency evidence. | Fine-mapping is invalid when association signs and LD signs use different effect alleles. |
| Sample size | Invalid or missing effective sample size causes a locus failure; the old `10,000` fallback was removed. | An invented sample size changes Bayes factors and posterior probabilities. |
| LD validation | Variant order, coordinates, alleles, dimensions, finite values, diagonal, symmetry, correlation bounds, eigenvalues, and LD/z consistency are checked. | FINEMAP and SuSiE require the z vector and LD matrix to describe the same ordered, allele-coded variants. |
| LD failure routing | SuSiE retains the exact LD validation reason. Structural errors and severe LD/z mismatch fail the locus immediately; only a finite non-PSD matrix enters bounded repair. Ordinary fitting failures retry only the already validated LD. | Numerical convergence cannot make scientifically incompatible LD valid, and non-convergence alone does not justify altering a valid LD matrix. |
| LD repair | SuSiE repairs a non-PSD matrix before any further fit, records the repair, revalidates the complete LD/z contract, and rejects a repair whose maximum correlation change exceeds 0.05. FINEMAP does not silently repair LD. | Large repairs can manufacture a materially different likelihood, and repaired LD must pass the same validation as original LD. |
| Variable effective sample size | For every locus, both engines record NEF minimum, maximum, median, relative range `(max-min)/median`, the selected median, policy, threshold, and warning reason. The configured `warn` policy continues analysis but marks material heterogeneity in locus QC and successful credible-set outputs. | FINEMAP and `susie_rss` consume a scalar locus sample size; the median remains an approximation and must not hide variant-level heterogeneity. |
| Credible-set warning provenance | Successful and recovered credible-set outputs carry `analysis_status`, `outcome_reason`, NEF diagnostics, and `warning_reason`. Failed loci are recorded in the combined locus outcome/QC TSV with `failure_reason`, rather than being represented as nonexistent credible sets. | A failed LD or model fit produces no scientifically valid credible set; mixing failure-only rows into a credible-set table would misrepresent the result. |
| FINEMAP credible sets | `--prob-cred-set` defaults to `0.95`, follows the resolved YAML/CLI value, and is validated again during export; the selected causal-count model is deterministic, and each component is exported separately. | The coverage target must be reproducible, and model posterior and SNP PIP are different quantities that must not be interchanged. |
| FINEMAP model probability validation | Every exact `.cred<K>` output must contain exactly one finite `Post-Pr` value in `[0, 1]`. Missing, malformed, duplicate, non-finite, or out-of-range values invalidate that complete locus before causal-count model selection. Other loci continue, while the affected locus and every evaluated model retain the failure code and detail. | FINEMAP defines `Post-Pr` as the posterior probability of the represented number of causal variants. Treating corrupt output as zero, clipping it, or ignoring only one candidate can select the wrong causal-count model. |
| FINEMAP external-process timeouts | LDstore has one configured total per-locus stage limit and FINEMAP has one configured per-locus fitting limit. Each process runs in an isolated process group; timeout sends graceful termination, waits for the configured grace period, then force-kills the group if necessary. The locus fails with `ldstore_timeout` or `finemap_timeout`, partial scientific outputs are removed, and independent loci continue. | A runtime limit is an operational safeguard rather than a statistical threshold. Killing the complete process group and excluding incomplete outputs prevents a hung or partially written external analysis from being interpreted as a valid locus result. |
| FINEMAP controls | SSS is the default algorithm; official FINEMAP 1.4.2 defaults are canonical YAML values; SSS and conditional controls are forwarded only to their applicable subprogram. | A requested algorithm or threshold must affect the executed statistical model rather than being accepted and ignored. |
| SuSiE controls | Fitting, recovery, LD validation/repair, execution, memory, plotting, locus construction, MHC policy, genome build, and coverage are resolved from canonical YAML. R receives one resolved JSON document instead of independent argument defaults. | A validated or displayed setting must control the executed model; adapter fallbacks must not silently replace it. |
| Defaults and audit trail | Scientific/resource values live only in canonical YAML and its schema. Python compatibility values are derived from the validated model; R retains only protocol invariants. Each run records the complete resolved document and checksums. | Results must be reproducible and failures must not be hidden behind console-only messages or unexplained literals. |
| SuSiE probability semantics | Credible-set membership is the configured-coverage single-effect component set (`alpha`), while FLAMES `prob1` is the model-wide SNP PIP required by FLAMES. Both definitions and both coverage checks are recorded. | Component posterior weights and model-wide SNP PIPs answer different questions; silently treating them as interchangeable is scientifically misleading. |
| FINEMAP-to-FLAMES IDs | Credible-set rsIDs are mapped through the harmonized `.z` file to `CHR:BP:A1_A2`; IDs are no longer guessed by replacing underscores. | An rsID does not intrinsically encode chromosome, position, or allele orientation. |
| FLAMES files | Each file contains only `index`, `cred1`, and `prob1`; `indexfile.txt` contains `Filename`, `GenomicLocus`, and `Annotfiles`; a manifest records coverage/build/model metadata. | This follows the FLAMES example and the minimal formatter used by FUMA, without attaching misleading model-level comments to SNP-level columns. |
| Failure handling | Zero-task/all-failed runs raise errors, recovery placeholders are replaced in place, and only current successful loci enter FLAMES indexing. | A pipeline must not report success or merge stale output when no valid locus was produced. |
| SuSiE no-set outcome | A converged SuSiE analysis with no credible sets surviving the configured purity filter returns `completed_no_credible_sets`, records a null FLAMES handoff, and prevents FLAMES execution. | Optimization convergence and retained credible sets are distinct outcomes; absence of a retained set is scientifically valid but cannot satisfy the FLAMES input contract. |
| Overlapping locus results | Every requested locus is first fine-mapped independently. After that primary pass, connected overlaps among successful fitted boundaries are rerun as one union region without applying the flank again. The authoritative result combines non-overlapping primary credible sets with successful joint reruns and links every joint row to the superseded primary files and warnings. | Posterior probabilities from different regional models are not directly mergeable. A new joint fit uses one variant set and LD matrix, while retaining the complete fixed-boundary primary analyses as provenance. |
| SuSiE summary-statistics preparation | The genome-wide table is streamed once into partitions for chromosomes used by the effective loci. Each partition is loaded once and indexed by position to write one exact file for every primary boundary. Overlapping primary files deliberately repeat shared variants; only the post-primary joint round uses a union interval, and it reuses the chromosome cache. | This preserves the requested first-round regional models while removing worker-level full-file reads and locus-by-genome scans. The optimization changes I/O, not the variants assigned to a locus or the statistical model. |
| Dense-LD resource guard | Both engines reject a whole locus before LD construction when its harmonized variant count exceeds the canonical configured limit (30,000 by default). The count, limit, matrix/peak-memory estimates, warning/failure code, and override instructions are retained in locus QC and summaries. No SNPs are pruned to satisfy the cap. | Dense LD requires quadratic storage and downstream validation may be cubic. Failing the requested locus model is scientifically safer than silently selecting a smaller variant set; an explicit override documents acceptance of the additional computational risk. |
| SuSiE supervised-fit I/O | Each validated locus `z/LD/n` payload is serialized once as a read-only temporary RDS and reused by every independently supervised child fit. A repaired LD matrix receives a new payload only after complete LD/z revalidation. Attempt-specific `L`, iteration, purity, coverage, verbosity, and timeout controls remain separate, and payload counts/state are recorded in QC and recovery audit output. | Reusing an exact R serialization removes repeated quadratic writes and compression without changing `susie_rss` inputs, model controls, recovery decisions, or the hard-timeout process boundary. Keeping original and repaired LD states separate prevents a retry from fitting the wrong likelihood. |
| Reproducibility | Software versions, input harmonization QC, per-locus status, LD QC, failure reasons, and genome build are written. | These fields are needed to reproduce and audit fine-mapping results. |

The included unit tests verify exact FLAMES columns and IDs, reject a cumulative FINEMAP credible set below its configured target, validate FINEMAP model-probability boundaries and malformed output, preserve locus-scoped failure handling, and protect the existing return-key contracts.
